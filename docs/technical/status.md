# Паспорт, статус и словарь

[Навигация](README.md) · [Архитектура](architecture.md) · [Разработка](development.md)

**Срез: 2026-09-17, рабочее дерево.** Здесь «текущее» означает наличие соответствующего пути в исходниках. Список не является сертификатом работоспособности опубликованного релиза.

## Назначение

«Виджет отзывов» собирает отзывы с маркетплейсов, позволяет модерировать и публиковать их, а затем встраивает отзывы в сайт продавца. Администратор работает в SPA; посетитель магазина — с JavaScript-виджетом. Backend написан на Go, хранение использует GORM с SQLite/PostgreSQL, админка — React/TypeScript/Vite.

Self-hosted-установка автономна. Поддержка многопользовательской изоляции в общих модулях не делает её зависимой от облачной подписки.

## Словарь

| Термин | Значение в текущем коде |
|---|---|
| Тенант (`Tenant`) | Область владения данными. В обычной self-hosted-установке используется неявный тенант; в строгом режиме область определяется из сессии или публичного ключа. |
| Пользователь админки | Учётная запись с паролем, ролью и сессиями; не равен посетителю магазина. |
| Маркетплейс | Тип внешнего источника: `wb`, `ym`, `ozon`. Не идентификатор отдельного кабинета продавца. |
| Подключение | Сохранённые настройки и credentials тенанта для маркетплейса. Сейчас одна запись на пару `(tenant_id, marketplace)`. |
| Магазин / сайт | Домен и каталог, куда встраивается виджет. Не путать с кабинетом на маркетплейсе или с тенантом без уточнения контекста. |
| Товар | Внутренняя запись и связи с внешними товарами. Артикул продавца используется при сопоставлении и выдаче, но не заменяет все идентификаторы. |
| Импортированный отзыв | Отзыв из внешнего источника; обновление того же внешнего отзыва не должно создавать дубликат. |
| Отзыв с сайта | Пользовательская отправка через виджет с отдельной модерацией, согласием и обработкой медиа. |
| Публикация отзывов | Подготовка данных для публичной выдачи/экспорта. Не путать с отправкой ответа на маркетплейс. |
| Публикация настроек | Создание активной версии JSON-конфигурации виджета. |
| Контекст виджета | `product` или `homepage`: два назначения конфигурации, не два отдельных runtime виджета. |
| Публичный ключ | Идентификатор публичной области выдачи. Он виден в embed-коде и не является паролем администратора. |
| Артефакт | Собранная поставка. Версия исходника сама по себе не доказывает версию всех доставленных JS/CSS. |

Подробности ключей и связей: [данные и контракты](data-and-contracts.md).

## Известные технические границы

### Один аккаунт на маркетплейс

Уникальность credentials закреплена в [MarketplaceCredential](../../internal/store/marketplace_credentials.go). Идентичность отзывов и состояние синхронизации также завязаны на тенант и маркетплейс. Несколько независимых кабинетов одного МП потребуют изменения всей цепочки, а не дополнительного поля формы. Для текущего этапа такое расширение отложено.

### Конфигурация редактора и виджета пока описана отдельно

[TypeScript](../../web/admin/src/widgetConfig.ts) и [JavaScript](../../web/reviews-widget/reviews-widget.js) поддерживают значения по умолчанию и нормализацию вручную. Общее определение опубликованного формата — принятое направление, ещё не завершённая миграция. Черновик может содержать незавершённые поля; опубликованный контракт должен быть однозначным.

### Не все сборки обновляют встроенную SPA

[Dockerfile](../../Dockerfile) пересобирает админку. [Сборщик бинаря](../../deploy/build.sh), [VPS source-deploy](../../deploy/server-deploy.sh) и [бинарная часть release workflow](../../.github/workflows/release.yml) напрямую компилируют Go. Они зависят от состояния `internal/server/admin_dist`.

Одна только успешная команда `go build` не доказывает свежесть фронтенда. Принятое направление — согласованный контейнер с сервером и ресурсами из одного снимка исходников.

### Базовая проверка рабочего дерева не равна зелёному CI

В ходе предыдущей работы отмечены конфликты сигнатур resolver-callback в `admin_questions_test.go`, `question_publish_test.go`, `reply_publish_test.go`. Это состояние рабочего дерева, а не гарантированная ошибка любого checkout. В рамках подготовки документации полный набор тестов не объявляется прошедшим. Если проверка использует временный overlay, её результат нельзя выдавать за проверку неизменённого дерева.

## Как отличать факт от намерения

- Общий runtime виджета уже существует; единая гарантированная доставка всех ресурсов ещё требует работы.
- Точки расширения backend существуют; стабильного внешнего SDK из них автоматически не получается.
- Цель — единственная общая оболочка админки с дополнительными компонентами; наличие отдельной поставки не оправдывает копирование её общих страниц.
- Производительность и допустимое число одновременно работающих клиентов устанавливаются измерением. Здесь нет обещания ёмкости без нагрузочного сценария.

Для нового изменения сначала определите: какую сущность оно меняет, какой инвариант сохраняет, какой пользовательский сценарий это подтверждает. Затем переходите к [руководству контрибьютора](development.md).
